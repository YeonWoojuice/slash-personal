# slash-api ↔ slash-llm

> 상태: **초안.** 팀 합의 후 확정
> 최종 수정: 2026-08-03 · 작성: 주연우

Gemma 추론 서비스입니다. 요약과 상태 설명을 담당합니다.

---

## 전달 방식

| 시기 | 방식 |
|---|---|
| 현재 (개발 초기) | HTTP 직접 호출 |
| 이후 | SQS Job 수신 → 처리 → `slash-api` 결과 API 호출 |

GPU 추론은 수 초가 걸리므로 사용자 HTTP 연결을 붙잡지 않습니다.
최종 구조에서는 `slash-api`가 Outbox를 거쳐 SQS로 발행하고, `slash-llm`이 소비합니다.

**아래 규격은 두 방식에서 동일합니다.** 전달 경로만 바뀝니다.

---

## 모델

| 항목 | 값 |
|---|---|
| 모델 | `gemma3:4b` (instruction-tuned) |
| 실행 | Ollama |
| 배포 | EKS GPU Node, Worker 1개 |
| 재시도 | 최대 3회 → DLQ |

---

## 요약

```
POST /internal/v1/llm/summary
```

### 요청

```json
{ "text": "요약할 원문" }
```

| 필드 | 필수 | 제한 |
|---|---|---|
| `text` | O | **150자 이상 8000자 이하** |

### 응답

```json
{
  "summary": "요약문",
  "model": "gemma3:4b"
}
```

### 입력 길이 제한

| 조건 | 처리 |
|---|---|
| 150자 미만 | **400** 반환 |
| 8000자 초과 | 앞에서 8000자만 사용 |

150자 미만을 막는 이유 — 짧은 문장을 요약시키면 모델이 분량을 채우려고
**원문보다 길게 늘여 씁니다.** 아래는 실제 사례입니다.

```
입력: "이따 8시에 뚝섬 가는데 비 오나 확인해줘"
출력: "이따 오후 8시에 뚝섬에 가려고 하는데, 그 시간의 날씨를 확인해달라.
       비가 오는지 여부를 알려주어 실내 대체 계획을 논의하고 싶다. …"
```

이런 입력은 애초에 `TEXT_SUMMARY`가 아니라 `WEATHER`로 분류되어야 합니다.
**`slash-nlu`에서 걸러지는 것이 정상이고, 여기서는 2차 방어입니다.**

### 오류

| 상태 | 상황 |
|---|---|
| 200 | 성공 |
| 400 | 길이 제한 위반 |
| 500 | Ollama 연결 실패 또는 추론 오류 |

500일 때만 재시도하십시오. 400은 재시도해도 동일합니다.

## 상태 설명 (2단계)

`SYSTEM_STATUS` 원본 수치를 사람이 읽을 문장으로 바꿉니다.

```
agent가 수치 반환 → slash-api 검증 → SQS → slash-llm 설명 생성
```

원본 수치는 `slash-api`가 그대로 보관합니다. **설명문은 참고용이며 원본을 대체하지 않습니다.**

---

## 지켜야 할 것

**Gemma에게 사실을 묻지 않습니다.** 모델은 외부 정보에 접근할 수 없고,
모르는 내용을 그럴듯하게 지어냅니다.

날씨·환율·뉴스 등은 각각 담당 API로 라우팅하고, Gemma는 **주어진 텍스트를 가공하는 일만** 맡습니다.

프롬프트에도 아래를 명시하고 있습니다.

```
- 원문보다 짧게 쓴다
- 최대 3문장
- 요약문만 출력하고 다른 말은 붙이지 않는다
- 원문에 없는 내용은 지어내지 않는다
```

## 환경변수

| 이름 | 기본값 | 설명 |
|---|---|---|
| `OLLAMA_URL` | `http://localhost:11434` | Ollama 주소 |
| `LLM_MODEL` | `gemma3:4b` | 모델 |
| `LLM_TIMEOUT` | `120` | 응답 대기(초) |
| `SUMMARY_MIN_CHARS` | `150` | 최소 입력 길이 |
| `SUMMARY_MAX_CHARS` | `8000` | 최대 입력 길이 |
